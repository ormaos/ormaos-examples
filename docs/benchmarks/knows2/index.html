knows2: what an agent knows about an execution

N = 108 runs: 9 tasks x 4 arms x 3 runs, model claude-opus-5-5, 2026-11-28. An agent gets the folder an execution left and questions about what happened in it, written by a model that was not told what Ormaos records; its answers are graded against an oracle that reads neither the trace nor the recording.

Ormaos records and shows what happened inside your Python execution — the runtime context for your agent and for you.

Method

The questions: a writer that was not told about Ormaos

For each task, claude-opus-5-5 wrote the questions once, in bubblewrap, in a folder that held only the source files of the program, its README, and what the execution printed (stdout.txt, stderr.txt). No input file, no file the execution wrote, no .venv, no .ormaos, no trace; nothing in the folder or in the prompt names Ormaos or says that the execution was recorded or traced. Where a README or the notebook spoke of Ormaos, those words were taken out for the writer. No question was edited, reworded or replaced. The prompt, after its first two sentences (what ran, what the folder holds):

The writers wrote 72 questions; 71 are kept. An agent gets each question with the writer's words and the writer's format. The writer's folder, prompt, transcript and questions are in agent-bench/knows2/writer/.

The oracle: one more execution, under sys.settrace

The answers come from one more execution of the same program, independent of the arms, under sys.settrace, with wrappers around open and sqlite3.connect. oracle.py computes every answer from that trace and from the files that execution left. It never reads an Ormaos recording or a VizTracer trace.

Rules written before any agent ran

Each question has a rule in rules.json, written, with the oracle, before any agent ran: numbers equal in value, names compared by their last dotted part, lists in order or as sets, a word out of a few without regard to capitals, a number rounded to the decimals its format names. An answer is right or wrong as a whole. The score of a run is the share of the task's kept questions it got right. Every answer is counted as right (by the rule of its question), null (the agent wrote null) or wrong (not null, and the rule marks it wrong).

The drop rule

A question is dropped only when the oracle cannot give one unambiguous answer to it: not because an arm cannot answer it, not because it is hard, not because of what any agent answered. Dropped:

  • ai-app, q1, "On which TCP port on 127.0.0.1 did the model_server stand-in listen during this run?": the server listens on a free port the system picks (("127.0.0.1", 0)): the oracle's execution and the execution of each arm got different ports

The container

Each run copies the task's folder and mounts it at /srv/<task> in a new container of one image: Ubuntu, Python 3.14.4 and uv, with the agent's command line (claude-code 2.1.322) added as one layer. The containers are on a network without a route out; the only way out is a proxy that answers for api.anthropic.com and refuses every other host. Before the first run a canary on that network checked that https://github.com and https://raw.githubusercontent.com do not answer and that the model's host does. Each run gets a new home folder that holds the agent's credential and nothing else, the prompt, the tools Bash, Read, Grep, Glob, Edit and Write, and a time limit of 900 s. The folder a run leaves is graded outside the container, by a process that is not told which agent ran. The harness: agent-bench/harness. The execution was played once per arm and once more for the oracle, in separate copies mounted at the same path, and the build stopped if the copies did not leave the same files.

The first attempt counts

Every slot (task, arm, run) was run once, and every run counts: nothing was run again and nothing is left out. Runs that ended out of time, with an error, or without an answers.json that reads as JSON: 0.
