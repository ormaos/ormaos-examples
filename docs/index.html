Ormaos

Ormaos records and shows what happened inside your Python execution — the runtime context for your agent and for you.

The problem

A scheduled Python job prints sync finished: OK, exits without an error, and in the morning the stock of some products is wrong. The run cannot be repeated and nothing was logged, so whoever investigates, a person or a coding agent, has only the code and the data that is left.

Reading a recording by hand

The demo job, order-sync, in a fresh copy: install Ormaos, record one run, then read the recording. The summary names an exception that was caught and never seen; the next commands show where it was raised and handled, the calls below the handler, and the I/O they did.

A real terminal session, not edited. Pauses are shortened during playback.

An agent, without and with the recording

The same job on the morning after a night run that cannot be repeated. A coding agent gets the folder and one sentence: the run said OK, some products have wrong stock, find out why. On one side the folder has last night's recording, on the other it has not.

5 of 5runs with the recording stated the cause as proven
0 of 5runs without the recording stated the cause as proven

Measured: N = 5 runs per side, model claude-opus-5-5, each run started with only the prompt, in a sandbox that holds only its own folder.

On both sides, every run named the except that skips orders and the orders that were skipped. The difference is the reason for the skips. With the recording, the answer gave the exception type, how many times it was raised, and the lines where it was raised and handled, as what happened last night. Without it, every answer said the reason could not be confirmed and left other causes open.

On neither side could a run say what exactly was wrong in the text of the rejected values: Ormaos records shapes (types, lengths, structure), never values.

A terminal recording of one run per side is not on this page yet.

Try it in 3 commands

git clone https://github.com/ormaos/ormaos-examples && cd ormaos-examples/order-sync
python3 -m venv .venv && .venv/bin/pip install git+https://github.com/ormaos/ormaos-python
./reset.sh && .venv/bin/ormaos run -- .venv/bin/python job.py

The job's own output comes first, unchanged. Then Ormaos prints a short summary on stderr, and its last line gives the next command to run. What is needed to install it, and everything else, is in the README.

Not yet

  • A package on PyPI. Install from GitHub.
  • A stable file format. Today's is provisional.
  • Windows and macOS: not tested.
  • Reading commands for a folder other than ./.ormaos.
  • Line-by-line reading for tree, exceptions, io, path and diff.
  • A way to know which signal ended a process that nothing waited for.
  • Web servers that start worker processes (uvicorn, gunicorn) in the compatibility matrix.
